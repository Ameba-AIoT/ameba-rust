# rtl8721f-pac

[![License](https://badgen.net/badge/License/Apache%202.0/lightgrey)](../../../LICENSE)
[![Target](https://badgen.net/badge/target/thumbv8m.main/blue)](https://doc.rust-lang.org/rustc/platform-support/thumbv8m.main-none-eabi.html)

Peripheral access crate for the RTL8721F, generated by
[`svd2rust`](https://docs.rs/svd2rust/). Provides type-safe register access for
roughly 89 peripheral blocks and the 79-entry interrupt vector table.

Part of the [ameba-rust](../../../README.md) SDK. Most applications don't depend
on this crate directly — [`ameba-hal`](../../README.md) re-exports it as
`ameba_hal::pac` and wraps it in higher-level drivers.

## Usage

Prefer the HAL. Reach for the PAC when you need a register the HAL doesn't yet
expose:

```rust
use ameba_hal::pac::{self, gpio_reg};

const GPIOA: *const gpio_reg::RegisterBlock = pac::GpioReg::PTR;

let regs = unsafe { &*GPIOA };
let direction = regs.gpio_ddr().read().bits();
regs.gpio_ddr().write(|w| unsafe { w.bits(direction | 1 << 14) });
```

Generated accessors make invalid writes a compile error: a two-bit field only
accepts values it can hold, and a read-only register has no `write` method.
Field-level accessors are used where the SVD describes the fields; `bits()`
covers registers described only as a whole word.

### Secure and non-secure apertures

Every peripheral is mapped twice — a non-secure base and a secure alias
`0x1000_0000` above it. The base addresses baked into this crate are the
non-secure ones, which is what drivers should use by default. Derive addresses
from each peripheral's `::PTR` constant rather than writing literals; a
hand-written address that is off by one aperture reads plausible-looking garbage
instead of faulting.

## Generated code

This crate is generated code, not hand-maintained source. Don't hand-edit
`lib.rs`, `src/` or `device.x`.

## Features

| Feature | Default | Effect |
|:--------|:--------|:-------|
| `rt` | off | Emits the interrupt vector array, consumed via `cortex-m-rt`'s `device` feature |

Enable `rt` here and `device` on `cortex-m-rt` together, or neither: turning on
only one duplicates or omits the vector array at link time.
[`ameba-hal`](../../README.md) and [`ameba-rt`](../../../ameba-rt/README.md)
already set both consistently.
